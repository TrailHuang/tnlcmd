对 tnlcmd 项目 `internal/` 目录全部 10 个 Go 文件进行了代码审查，并按顺序修复了 10 个 issue：

### 修复的文件
- `internal/history/history.go` — Issue #1: `maxSize<=0` 时 `h.history[1:]` 对空切片切片导致 panic；增加 `maxSize<=0` 防御性检查。
- `internal/commandtree/command_tree.go` — Issue #2/#3/#7/#10:
  - `GetNumberCompletions` 从 `Description`（固定值"Range parameter"）提取范围导致始终返回 nil，改为优先用结构体字段 `RangeMin/RangeMax`。
  - `isValidNumberInRange` 忽略结构体字段从 Name 重新解析导致范围检查可被绕过，改为优先用结构体字段。
  - `extractNumberRange`/`extractEnumValues` 每次调用重新编译正则，提升为包级预编译变量 `numberRangeRegexp`/`enumValuesRegexp`。
  - `findCommand` 中 `append(path,...)`/`append(matchArgs,...)` 的底层数组共享风险，改用 `make+copy` 显式复制。
- `internal/completer/completer.go` — Issue #4: `GetCurrentViewCommands` 中 `strings.Fields(name)[0]` 对空切片越界 panic，增加 `len(parts)==0` 检查。
- `internal/session/session.go` — Issue #5: `normalizeLineEndings` 中 `Contains(text,"\r\n") && !Contains(text,"\n")` 永远为 false 的死代码，改为语义正确的 `!Contains(text,"\n")` 快速返回。
- `internal/cmdline/cmdline.go` — Issue #6/#8:
  - `quit` 命令描述"Exit to previous mode"与绑定的关闭连接 handler 不一致，改为"Exit and close connection"。
  - `SetConfig` 中 `maxhistory`/`port` 的 `Atoi` 错误被 `_` 吞掉导致 `MaxHistory=0`（触发 Issue #1 panic）或 `Port=0`，改为返回错误。
- `internal/mode/mode.go` — Issue #9: `SetPrompt` 未检查 `#` 后缀导致 "config#" 被追加成 "config#> "，对齐 `NewCommandMode` 逻辑。

### 项目关键事实
- tnlcmd 是一个 Go 实现的 telnet 命令行服务器，模拟 Cisco 风 CLI（模式切换、命令树、补全、历史）。
- 模块结构：`cmdline`(门面) → `server`(telnet) → `session`(连接处理) → `mode`/`commandtree`/`completer`/`history`。
- 每个 `CommandMode` 拥有独立 `CommandTree`，`CommandNode` 含 `RangeMin/RangeMax`、`EnumValues` 结构体字段。
- 模块路径：`github.com/TrailHuang/tnlcmd`。
